# Architecture

Internal IT asset tracking system for the IT department. Python desktop app, compiled to Windows exes via PyInstaller, deployed across an internal Windows domain network.

## Architecture (4 Python apps → source payloads → 1 unified installer)

| File | Builds to | Runs on |
|------|-----------|---------|
| `server.py` | source: `run_server.py` | The **Asset Server** - what every window, popup and tray entry calls this component, while the Windows Service, the IIS site and the install directory keep the names they were installed under (see below). Runs on `asset-server`, permanently. Flask REST API + SQLite + background jobs; the interactive GUI's Tkinter console is `server_gui.py` (#207) - imported at module level and bound the way `server_cert.py` is, below. Minimises to system tray. **One program, three modes:** a Windows Service (`AssetManagerServer`, headless — `install`/`start`/`stop`/`remove` verbs, session-0 detected by `_launched_by_scm()`); a headless foreground `serve` mode for IIS HttpPlatformHandler; and interactive GUI mode, which becomes monitor-only when the port is already served — and **says who is serving when that is IIS**: `iis.json` beside the server is the record `install-iis.ps1` leaves of what it bound, `_iis_host()` is the one thing that reads it, its own module beside this one since #243 (`server_iis.py`), and the three surfaces that used to assume this process was the server — the banner, the tray's Quit, Server Settings — each name the app pool instead. **A fourth reader came with #176 and is not about naming the host but about the protocol**: `_iis_tls_bound()` answers whether IIS is terminating TLS in front of this process, and it is what the banner, the tray and the liveness probe tell HTTP from HTTPS by. It asks `cert_thumbprint` in that same file first and **asks the port itself where that says nothing** (#185, `_port_serves_tls`), because that key has exactly one writer - `install-iis.ps1` - so a certificate bound in IIS Manager, bound after that script ran, or bound to a site it never ran against leaves it empty over a site serving https, which read as HTTP on every one of those four surfaces. The probe is a TLS handshake against `127.0.0.1` and nothing else: no request, no credential, nothing read back, so it verifies nothing and is not rule 1 turned off - rule 1 is a client deciding whether to trust a server, this is a server asking what its own port is doing. Cached for a minute, `_remote_tls_ok` asking it per request — `ssl_enabled` in `server_config.json` has one writer, this console's own SSL Certificate install, so it is false on every IIS install, and under `-PfxPath` or `-CertThumbprint` there is no `ssl_key.pem` on the machine at all. Missing, unreadable, not JSON or not an object all mean not IIS, so a Service install and a hand-started launcher behave exactly as they did. |
| `server_cert.py` | (imported, not built) | `asset-server`, inside the server process. The certificate lifecycle of ADR-0020 and nothing else: `_stage_new_cert` writes a self-signed pair bound to nothing (C1), `_push_next_cert` queues `trust_cert` for every Client through `_queue_command` (C3), `_clients_behind_staged` counts who has not collected it off the command queue rather than off `clients.cert_fingerprint`, `_cut_over_cert` copies the live pair into `cert_rollback\` and replaces it (C4), `_export_public_cert` writes the public half and refuses a file holding a key (C5), with `_cert_fingerprint`, `_cert_to_pem` and `_cert_names` around them - a fourth, `_bind_cert_command`, moved out to `server_iis.py` at #243, the elevated command being about the *binding* and not a certificate; `server_cert.py` imports it back rather than defining it, since `_cut_over_cert`'s payload still carries it. **Its own module since #206** rather than a good idea about tidiness: it sat inside the Server GUI block while being no part of it - no tkinter, no widget - and `GET /clients` and `POST /clients/push_cert` both reach into it, so lifting the window out around it would have made two routes import the console. **It owns no paths.** `BASE_DIR`, the four certificate paths and `CERT_ROLLBACK_DIR` stay `server.py`'s, resolved once against the install directory and handed over by `server_cert.bind()` at import - thirteen names in all, the six above plus the seven helpers the moved code calls (`_log_event`, `_queue_command`, `_client_rows`, `_command_rows`, `_command_status`, `_admin_password_ok`, `_iis_host`). Handed over rather than imported back, because `server.py` runs as `__main__` under `applaunch`'s `runpy.run_path`: an `import server` there would execute a second copy of the whole server instead of reaching the one running. Three functions whose default argument was one of those paths take `None` and resolve it in their first line, a default being bound before `bind()` has run. |
| `server_gui.py` | (imported, not built) | `asset-server`, inside the server process. The Tkinter console `run_gui()` opens in interactive mode. **It is the console's shell since #235** - the twelve asset and admin windows are the nine `gui_*.py` modules below, imported here and re-exported under their own names, and what is left in this file is the door, the unsaved tracking, the small readers several windows share, `THEME`, and `run_gui` itself. The windows its section bar reaches - Manage Assets, Asset Sync, Backup/Restore, Mail Settings, Notification Rules, Capability Passwords, Server Settings - and the console door behind them, `_console_unlock`. Connected Clients is not among them since #260/085, Asset Proposals since #261/086, the System Log since #262/087 and Manage Transaction History since #263/088: each is a section's pane rather than a window, so it opens nothing and takes no guard. Only the last sits behind a door, and it is the same `_console_unlock` - the pane shows a row naming it until the console is open. Where they differ is what the section around them holds - Clients carried that one entry and became the pane itself, while Assets keeps Lookup Sheet and Asset Sync as rows with the proposals list beneath them, which is the shape `section_pane`'s third argument is. **Lifted out of `server.py` by #207** the way `server_cert.py` was by #206: 7,689 lines that were one concern with one entry point, reached by nothing else. **It owns no state of its own beyond what it draws with** - `THEME`, the console's unlock and unsaved-edit tracking (`_CONSOLE_UNLOCKED`, `_CONSOLE_UNSAVED`) move with it, but `ADMIN_CFG`, `PORT`, every `_save_*`/`_log_*`/`_sync_*` helper and dozens more stay `server.py`'s. Reaching for that many names one at a time the way `server_cert.bind()` does would be a second copy of `server.py`'s own globals, so `bind()` here stores the **module object** instead - `S = None` at import, `server.py` calls `server_gui.bind(sys.modules[__name__])`, and every reference to a name that stays in `server.py` is written `S.<name>`, read off that live module at call time. `import server_gui` sits at `server.py`'s module level, not deferred, so this module has to import cleanly with no display (`tkinter` stays inside the functions that draw) the same way `server_cert.py` does. |

It is a **pair** rather than one call because the decision has to be made before the window is built: `raise_open(key)` answers with the window already open - deiconified, lifted and focused - and `None` where there is none, and `single(win, key)` registers what was built and drops the key on that window's own `<Destroy>` and **not** a child's, which is `ImageBank`'s trap one behaviour over. The key is what the window is **about** rather than who asked for it, which is what made the Server GUI's feed row and its Transactions section entry one Manage Transaction History until 088 made that table a pane, one by construction - and a window about a row is keyed on the row (`transaction_detail:<id>`, `cancel_transaction:<id>`), two rows being two windows. A class-based window takes the `raise_open` at its **construction site** and keeps the `single` inside itself, an `__init__` having no way to abort cleanly. The transient prompts opened from inside a window that already grabs are deliberately not guarded, and neither are the four windows above that must refuse their own X. `tools/server-checks.py` and `tools/client-checks.py` each open every guarded window twice and assert that the second request built nothing, answered with the window already open, and that closing it lets the next one open. **`flash` is the fifth of these, and it is the *opposite* of a raise** (#193): a window with something to say while somebody is working in another application had one spelling in this product, which was `deiconify()` + `lift()` + `-topmost`, and that does not ask - it takes the screen off whatever was in front of it, on a machine where that is somebody mid-scan. `FlashWindowEx` with `FLASHW_TRAY | FLASHW_TIMERNOFG` flashes the **taskbar button** and then leaves it highlighted until the window is brought to the foreground, which is where Windows already says *this app wants you* and is the one signal here that survives being ignored for ten minutes. It never raises, never focuses and never raises an exception - `ctypes` and `user32` are guarded the way `pillow` is throughout this file, since a notification that could not be flashed is still a notification on the window - and it asks `GetAncestor(hwnd, GA_ROOT)` rather than `winfo_id()` alone, Tk on Windows handing out the HWND of its own inner window while the taskbar button belongs to the frame above it, so flashing the inner one is a call that succeeds and does nothing visible. **`ScrollRegion` is the sixth of these, and the argument is about a form nothing bounds** (#199): a card per Engineer, a card per capability password and a card per notification rule each grow by a ticket rather than by anything the window can impose, and a form with no bound meets `fit`'s clamp - the height is taken from what the children ask for and then clamped to the screen, and `pack` gives the shortfall to whatever it served last, so what is lost is the rows themselves and not the tail of a list somebody can scroll to. It is a `tk.Frame` windowed into a `tk.Canvas`, which is the one shape `measure_scrolled_body` in `tools/client-checks.py` measures - a region built some other way is not a check that fails, it is a check that silently stops measuring - with a **ttk** scrollbar so it takes the palette through its style, the wheel bound **on the window** for `escape_closes`' reason and never with `bind_all`, and `size()` asked **beside** `fit` on the same repaint: laid flat, the window reports what everything *but* the region needs and what is left of the screen is what the region may have, so a form that fits opens exactly as tall as itself with nothing to scroll and one more card lengthens the scroll rather than the window. `width()` is the other half of that, a frame windowed into a canvas not passing its request up, so the window's own `reqwidth` is the canvas's configured width whatever is inside it. What it deliberately does not do is shrink a card to make room, a form legible for four rows and illegible for eight being the same bug deferred; and the footer is **outside** it and packed `side="bottom"` first, since a Close inside the scrolling body is a Close that can be scrolled away from. It is used at the two windows #199 converted - the Server GUI's Notification Rules and the Notifier's Remote Admin one - which is one behaviour in two apps and so rule 10's, while the hand-rolled regions that predate it are left alone: each is inlined into a window's own layout. There are thirty-two masked fields across the four apps, so the alternative to one helper is the same eight lines written thirty-two times, and the thing that would drift is which of them re-masks. It is `reveal(entry)`, taking the field and nothing else, and the control is **placed inside the entry** (`relx=1.0, rely=0.5, anchor="e"`) rather than packed beside it: an Entry is a geometry master like any other widget, and `place` is independent of what the parent uses - which is the whole of why not one of those call sites had to change its layout, across forms laid out with `pack` and with `grid`, fields built inside shared `field()` helpers, and one that is gridded conditionally long after it is constructed. The mask is **read back off the entry** rather than assumed - `MASK` here is `\u25cf`, which twenty-seven sites state for themselves and one stated as `\u2022` - so a field goes back to its own mask and none is quietly restyled. Off by default, per field and never remembered: there is no setting, nothing is written anywhere, and a `<Destroy>` re-masks, which is belt and braces stating the rule that a revealed field never outlives its window. The colour is the module-level `_LIVE`, the palette `Theme._bind` last bound, because this is the one drawing function here handed no colour and holding no widget to read one back off - and a literal there is exactly the widget the retint walk cannot recognise, left dark inside a light window. **What it cannot reach it does not pretend to**: `simple_password_prompt` in `server.py` is a `simpledialog`, which builds its own entry and hands back nothing but the string, so it is the one password field in these four apps with no toggle and says so where it is. **Nothing about a password reaching the System Log changes** - `_log_event` is still never handed one (rule 7's neighbour, and `tools/server-checks.py` asserts it as source) - and the two **replayable** secrets' windows still open **empty**: `GET /admin/mail` answers whether one is stored and never what it is (ADR-0013, ADR-0014), so the toggle there can only ever show what somebody typed a moment ago. Both gates drive the real windows rather than counting call sites: a control placed inside another widget is precisely what a source read cannot see. Toolbars take full labels on one row, then short labels on one row, and only then wrap - still at short labels; footers take equal columns capped at 210px. A drift there shows nothing at the time and nothing afterwards either: that same walk maps a widget by looking its colour up in the table it was *supposed* to have been drawn in, so one painted from a drifted literal has no entry, is skipped, and stays dark inside a light window while everything around it repaints. `cascade-audit.py` fails an app that writes one, and fails a `Theme` that stops seeding them. **And since #178 the faces are written down here the same way** - `FAMILIES` is the three typefaces this product draws in, `ROLES` says what each level of text *is* rather than how big it is, and `font(role)` is what a call site asks, bound into each app's globals by `Theme` beside the colours. | `client_update.py` | (imported, and run as a script) | Every client machine. What applies the next release in place, so an engineer is not sent to a browser and an installer for a change to a `.py` file. **Two phases in one file, and the split is the whole design.** Phase one runs *inside* the app: `update_now` resolves the zip off `GET /version`'s `client_packages`, downloads it through `common.py`'s pinned session (rule 10, rule 1), and checks the size, the SHA-256 the server published and the manifest - that it is this app, at the version `/version` called `latest`, built for the Python minor version now running (rule 13), and that **every name in it stays inside the install** - **before anything is stopped**.
